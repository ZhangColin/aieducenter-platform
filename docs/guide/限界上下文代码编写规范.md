## 一、包结构规范

### 1.1 标准包结构

每个限界上下文采用 DDD 六边形架构，包结构如下：

```
com.aieducenter.{context}
├── package-info.java           # 上下文说明（JavaDoc）
├── domain/                     # 领域层
│   ├── aggregate/              # 聚合根
│   ├── entity/                 # 实体
│   ├── repository/             # 仓储接口
│   ├── service/                # 领域服务（按需创建）
│   ├── error/                  # 领域错误定义（CodeMessage 枚举）
│   └── enums/                  # 领域枚举（独立文件）
├── application/                # 应用层
│   ├── dto/                    # 数据传输对象
│   │   ├── command/            # 命令 DTO（写操作）
│   │   ├── query/              # 查询 DTO（读操作）
│   │   └── response/           # 响应 DTO
│   ├── mapper/                 # 领域对象与 DTO 转换器
│   └── {Scenario}AppService.java    # 应用服务
├── infrastructure/             # 基础设施层
│   ├── persistence/            # 持久化实现
│   ├── redis/                  # Redis 缓存实现
│   ├── messaging/              # 消息队列适配器
│   └── {technology}/           # 其他技术适配器（按需）
└── endpoints/                  # 北向接口适配器层
    ├── controller/             # REST API
    ├── api/                    # 外部 API
    ├── listener/               # MQ Listener
    └── scheduler/              # 定时任务
```

**infrastructure 层组织原则**：

- 按技术栈拆分子包
- `persistence/` - JPA Repository 实现
- `redis/` - Redis 缓存实现
- `messaging/` - 消息队列适配器
- 其他技术按需创建子包

**示例**：
```
infrastructure/
├── persistence/
│   └── SpringDataJpaAdminUserRepository.java  # 实现领域层 Repository 接口
├── redis/
│   └── RedisSessionRepository.java            # Redis 缓存实现
└── messaging/
    └── RabbitMQMessageSenderAdapter.java      # 消息队列适配器
```

### 1.3 六边形架构层次职责

每个限界上下文采用 DDD 六边形架构（端口适配器架构），清晰划分层次职责：

```
        ┌─────────────────────────────────────┐
        │       北向接口（Driving Side）        │
        │  REST API | GraphQL | gRPC | MQ     │
        └─────────────────────────────────────┘
                        ↓
        ┌─────────────────────────────────────┐
        │      应用层（Application Layer）      │
        │  北向接口适配层 | 上下文出入口         │
        └─────────────────────────────────────┘
                        ↓
        ┌─────────────────────────────────────┐
        │       领域层（Domain Layer）          │
        │  核心业务逻辑 | 南向端口接口          │
        └─────────────────────────────────────┘
                        ↓
        ┌─────────────────────────────────────┐
        │      南向接口（Driven Side）          │
        │  密码加密 | 持久化 | 缓存 | 外部服务  │
        └─────────────────────────────────────┘
                        ↓
        ┌─────────────────────────────────────┐
        │    基础设施层（Infrastructure）       │
        │  南向接口的适配器实现                 │
        └─────────────────────────────────────┘
```

**层次职责说明**：

| 层次 | 职责 | 典型组件 |
|------|------|---------|
| **北向接口** | 外部调用入口 | REST Controller、GraphQL Resolver、gRPC Service、MQ Listener |
| **应用层** | 北向接口适配层，上下文出入口 | AppService、DTO、Mapper |
| **领域层** | 核心业务逻辑，按职责定义接口 | 聚合根、实体、领域服务 |
| **南向接口** | 需要的外部能力 | Repository、领域服务接口（如密码加密器） |
| **基础设施层** | 适配器实现 | JPA Repository、BCrypt 适配器、Redis 适配器、跨上下文调用接口及适配器 |

**关键原则**：

1. **应用层是上下文的出入口**：
   - 北向接口（REST、GraphQL 等）通过应用层访问领域逻辑
   - 其他上下文通过本上下文的应用层进行跨上下文调用
   - 应用层负责业务流程编排，不包含业务规则

2. **端口接口定义原则**：
   - **领域层需要**：在领域层按职责放置接口
     - 不强制使用 `port` 包，根据职责决定位置
     - 示例：密码加密器接口可以在 `domain/service/`
     - 适配器实现在基础设施层
   - **应用层需要**：接口定义和适配器都在基础设施层
     - 应用层可以依赖基础设施层
     - 接口和适配器分开文件（同一包下）
     - 示例：跨上下文调用

   **示例**：
   ```java
   // ========== 场景 1：领域层需要密码加密 ==========
   // domain/service/PasswordEncoder.java（领域层按职责定义）
   public interface PasswordEncoder {
       String encode(String rawPassword);
       boolean matches(String rawPassword, String encodedPassword);
   }

   // infrastructure/BCryptPasswordEncoderAdapter.java（基础设施层实现）
   @Adapter(PortType.CLIENT)
   public class BCryptPasswordEncoderAdapter implements PasswordEncoder {
       private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(10);

       @Override
       public String encode(String rawPassword) {
           return encoder.encode(rawPassword);
       }

       @Override
       public boolean matches(String rawPassword, String encodedPassword) {
           return encoder.matches(rawPassword, encodedPassword);
       }
   }

   // ========== 场景 2：应用层需要调用其他上下文 ==========
   // infrastructure/AdminUserClient.java（基础设施层定义接口）
   public interface AdminUserClient {
       boolean isAdminExists(Long userId);
   }

   // infrastructure/LocalAdminUserClientAdapter.java（基础设施层实现）
   @Component
   public class LocalAdminUserClientAdapter implements AdminUserClient {
       private final AdminUserQueryAppService adminUserQueryAppService;

       @Override
       public boolean isAdminExists(Long userId) {
           return adminUserQueryAppService.existsById(userId);
       }
   }

   // 未来拆分后：infrastructure/RemoteAdminUserClientAdapter.java
   @Component
   public class RemoteAdminUserClientAdapter implements AdminUserClient {
       private final AdminUserApiClient adminUserApiClient;

       @Override
       public boolean isAdminExists(Long userId) {
           return adminUserApiClient.checkExists(userId);
       }
   }
   ```

3. **南向接口适配器按技术拆分**：
   - `persistence/` - JPA Repository 实现
   - `redis/` - Redis 缓存实现
   - `messaging/` - 消息队列适配器
   - 其他技术按需创建子包

4. **框架依赖使用原则**：
   - 系统深度依赖 Spring Boot、Hutool，各层都可以直接使用这些库提供的能力
   - 尽量使用框架提供的能力，**不要自己实现工具方法、工具类**
   - 常用能力：
     - Spring Boot：依赖注入、事务管理、定时任务、消息队列
     - Hutool：集合工具（`CollUtil`、`MapUtil`）、字符串工具（`StrUtil`）、对象工具（`ObjectUtil`）
     - 不要重复造轮子，除非有特殊的业务需求

5. **北向接口类型**：
   - **REST Controller**：HTTP REST API（最常见）
   - **MQ Listener**：消息队列监听器，接收消息后调用应用服务
   - **GraphQL Resolver**：GraphQL API
   - **gRPC Service**：gRPC RPC 服务
   - **定时任务**：Scheduled Task（通过 `@Scheduled` 注解）

6. **跨上下文调用模式**：
   - **调用方**：接口和适配器都在基础设施层（分开文件）
   - **适配器**：注入被调用方的 Application 层
   - **好处**：未来系统拆分时，只需修改适配器实现（改为 HTTP/gRPC 调用）

   **示例**：Account 上下文调用 Admin 上下文
   ```java
   // ========== 调用方：Account 上下文（基础设施层）==========
   // infrastructure/AdminUserClient.java（接口定义）
   public interface AdminUserClient {
       boolean isAdminExists(Long userId);
   }

   // infrastructure/LocalAdminUserClientAdapter.java（适配器实现）
   @Component
   public class LocalAdminUserClientAdapter implements AdminUserClient {
       private final AdminUserQueryAppService adminUserQueryAppService;

       @Override
       public boolean isAdminExists(Long userId) {
           return adminUserQueryAppService.existsById(userId);
       }
   }

   // 未来拆分后：infrastructure/RemoteAdminUserClientAdapter.java
   @Component
   public class RemoteAdminUserClientAdapter implements AdminUserClient {
       private final AdminUserApiClient adminUserApiClient;

       @Override
       public boolean isAdminExists(Long userId) {
           return adminUserApiClient.checkExists(userId);
       }
   }
   ```

**示例：密码加密的六边形架构实现**：

```java
// ========== 领域层：按职责定义接口 ==========
// domain/service/PasswordEncoder.java
public interface PasswordEncoder {
    String encode(String rawPassword);
    boolean matches(String rawPassword, String encodedPassword);
}

// ========== 基础设施层：提供适配器实现 ==========

        return encoder.encode(rawPassword);

    @Override
    public boolean matches(String rawPassword, String encodedPassword) {

    }
}

// ========== 应用层：调用领域服务 ==========

        return adminUserRepository.save(adminUser).getId();
    }
}
```

## 二、领域层规范

### 2.1 聚合根（Aggregate）

**位置**：`domain/aggregate`

**命名规范**：`{Entity}.java`（无需后缀）

---

#### 小聚合原则（Small Aggregate）

**核心思想**：聚合应该保持小，只包含真正需要维护一致性的对象。

**原则要点**：

| 原则 | 说明 | 示例 |
|------|------|------|
| **1. 一个聚合根** | 每个聚合只有一个聚合根 | `AdminUser` 是聚合根，`AdminUserRole` 是实体 |
| **2. 保持小** | 聚合包含的对象尽可能少 | `AdminUser` 只管理 ID 集合，不加载完整的 `AdminRole` 对象 |
| **3. ID 引用** | 聚合间通过 ID 引用，而非对象引用 | `AdminUserRole` 存储 `roleId: Long`，而非 `AdminRole` 对象 |
| **4. 边界修改** | 修改聚合只能通过聚合根 | `adminUser.addRole(roleId)` 而非直接操作 `AdminUserRole` |
| **5. 事务一致性** | 聚合是事务一致性的边界 | 修改聚合内的所有对象在同一个事务中完成 |

**为什么保持小聚合**？

1. **性能优化**：减少数据库加载和锁竞争
2. **并发友好**：小聚合锁住的数据少，并发冲突概率低
3. **简单清晰**：职责单一，易于理解和维护
4. **一致性边界**：聚合是事务一致性的边界，保证聚合内对象的完整性

**应用服务与聚合的协作**：

应用服务方法可以涉及多个聚合，这是**允许且常见的**：
- **应用层定位**：北向接口的适配层，是限界上下文的出入口
- **职责**：组织聚合的业务职责及领域服务，完成一个系统故事（业务场景）
- **跨上下文调用**：其他上下文通过本上下文的应用层访问
- 应用服务可注入多个 Repository，查询并验证相关聚合的存在性
- 每个聚合内部的一致性由聚合根负责保证

**示例**：`assignRoles()` 方法
```java
import cn.hutool.core.collection.CollUtil;
import static com.cartisan.core.util.Assertions.requirePresent;

@Service
public class AdminUserManagementAppService {
    private final AdminUserRepository adminUserRepository;
    private final AdminRoleRepository adminRoleRepository;  // 可注入多个 Repository

    @Transactional
    public void assignRoles(Long userId, AssignRolesCommand command) {
        // 1. 查询并修改 AdminUser 聚合
        AdminUser adminUser = requirePresent(
                adminUserRepository.findById(userId),
                AdminMessage.ADMIN_NOT_FOUND
        );

        // 2. 应用服务批量验证其他聚合的存在（避免 N+1 查询）
        Set<Long> existingRoleIds = adminRoleRepository.findAllById(command.roleIds())
                .stream()
                .map(AdminRole::getId)
                .collect(Collectors.toSet());

        if (!CollUtil.containsAll(existingRoleIds, command.roleIds())) {
            throw new ApplicationException(AdminMessage.ROLE_NOT_FOUND);
        }

        // 3. 修改 AdminUser 聚合（只修改 ID 引用，不加载 AdminRole 对象）
        adminUser.clearRoles();
        for (Long roleId : command.roleIds()) {
            adminUser.addRole(roleId);
        }

        adminUserRepository.save(adminUser);
    }
}
```

**性能考虑**：

- 使用 `findAllById(command.roleIds())` 批量查询，一次数据库调用获取所有需要的角色
- 使用 hutool 的 `CollUtil.containsAll()` 检查请求的所有 ID 是否都存在，代码更可读
- 避免循环查询导致的 N+1 问题

**关键设计原则**：
- 聚合根通过 **ID 引用**其他聚合（`userRoles` 存储 roleId）
- 应用服务负责 **组织**多个聚合和领域服务，完成完整的业务场景
- 应用服务可注入多个 Repository，查询并验证相关聚合的存在性
- 聚合根 **不持有**其他聚合的对象引用
- 聚合根 **不查询**其他聚合（保持独立）

**分布式事务**：
- 当前系统未实现分布式事务（Sagas、2PC、TCC 等）
- 如需跨限界上下文的分布式事务，需要单独设计方案（待补充）

**错误示例**（大聚合）：
```java
// ❌ 错误：聚合根直接持有其他聚合根的对象引用
@Entity
public class AdminUser extends AuditableSoftDeletable implements AggregateRoot<AdminUser> {

    @OneToMany
    private Set<AdminRole> roles;  // 错误：应持有 ID 集合，而非完整对象

    @OneToMany
    private Set<AdminMenu> menus;  // 错误：AdminMenu 是另一个聚合根
}
```

**正确示例**（小聚合）：
```java
// ✅ 正确：聚合根只管理关联 ID，通过实体维护关系
@Entity
public class AdminUser extends AuditableSoftDeletable implements AggregateRoot<AdminUser> {

    @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
    @JoinColumn(name = "admin_id")
    private Set<AdminUserRole> userRoles = CollUtil.newHashSet();  // 只持有实体（含 ID）

    // 业务方法：通过 ID 添加角色
    public void addRole(Long roleId) {
        userRoles.add(new AdminUserRole(this.id, roleId));
    }

    // 获取角色 ID 列表（不加载完整对象）
    public Set<Long> getRoleIds() {
        return userRoles.stream()
                .map(AdminUserRole::getRoleId)
                .collect(Collectors.toSet());
    }
}
```

**聚合设计检查清单**：
- [ ] 聚合根只引用其他聚合的 ID，不持有对象引用
- [ ] 聚合内的实体使用 `@OneToMany` + `orphanRemoval = true`
- [ ] 实体不继承 `AuditableSoftDeletable`（建议）
- [ ] 聚合根继承 `AuditableSoftDeletable`（建议）
- [ ] 修改聚合边界需要通过聚合根的业务方法

**核心规范**：

```java
import cn.hutool.core.collection.CollUtil;
import static com.cartisan.core.util.Assertions.require;
import com.cartisan.core.domain.AggregateRoot;
import com.cartisan.data.jpa.annotation.EnumConvert;
import com.cartisan.data.jpa.domain.AuditableSoftDeletable;
import com.cartisan.data.jpa.id.TsidGenerator;
import com.cartisan.core.stereotype.Aggregate;
import com.aieducenter.admin.domain.entity.AdminUserRole;
import com.aieducenter.admin.domain.error.AdminMessage;
import com.aieducenter.admin.domain.enums.AdminUserStatus;

import jakarta.persistence.*;
import lombok.Getter;
import lombok.Setter;

/**
 * AdminUser 聚合根。
 *
 * <h3>职责</h3>
 * <ul>
 *   <li>封装管理员状态和行为</li>
 *   <li>管理登录凭证（用户名、密码）</li>
 *   <li>管理个人信息（昵称、邮箱、手机号、头像）</li>
 * </ul>
 *
 * <h3>不变量</h3>
 * <ul>
 *   <li>用户名不能为空且格式正确</li>
 *   <li>密码必须加密存储（由应用层负责加密）</li>
 * </ul>
 */
@Entity
@Table(name = "sys_admin_users")
@Aggregate
public class AdminUser extends AuditableSoftDeletable implements AggregateRoot<AdminUser> {

    private static final String USERNAME_PATTERN = "^[a-zA-Z][a-zA-Z0-9_]{2,19}$";

    // ========== 字段声明 ==========

    @Getter
    @Id
    @Column(name = "id", nullable = false, updatable = false)
    private Long id;

    @Getter
    @Column(name = "username", nullable = false, unique = true, length = 50)
    private String username;

    @Getter
    @Column(name = "password", nullable = false)
    private String password;

    @Getter
    @Column(name = "nickname", nullable = false, length = 50)
    private String nickname;

    @Getter
    @Setter
    @Column(name = "email", length = 255)
    private String email;

    @Getter
    @Setter
    @Column(name = "phone", length = 20)
    private String phone;

    @Getter
    @Setter
    @Column(name = "avatar", length = 512)
    private String avatar;

    @Getter
    @EnumConvert(AdminUserStatus.class)
    @Column(name = "status", nullable = false)
    private AdminUserStatus status;

    @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
    @JoinColumn(name = "admin_id")
    private Set<AdminUserRole> userRoles = CollUtil.newHashSet();

    // ========== 构造函数 ==========

    /**
     * 创建管理员。
     *
     * @param username 用户名（必填）
     * @param encodedPassword 加密后的密码（应用服务层已加密）
     * @param nickname 昵称
     */
    public AdminUser(String username, String encodedPassword, String nickname) {
        validateUsername(username);
        this.username = username;
        require(encodedPassword != null, AdminMessage.PASSWORD_WEAK);
        this.password = encodedPassword;
        this.nickname = nickname != null && !nickname.isBlank() ? nickname : username;
        this.status = AdminUserStatus.ACTIVE;
    }

    /**
     * JPA 默认构造函数。
     */
    protected AdminUser() {
    }

    /**
     * JPA 保存前生成 ID。
     */
    @PrePersist
    void prePersist() {
        if (id == null) {
            this.id = TsidGenerator.newInstance().generate();
        }
    }

    // ========== Getter ==========

    // 对于简单字段的读写，使用 Lombok 的 @Getter/@Setter
    // 对于有业务逻辑的字段修改，使用明确的业务方法

    public boolean isActive() {
        return status == AdminUserStatus.ACTIVE;
    }

    // ========== 业务行为 ==========

    /**
     * 修改密码（已加密）。
     *
     * <p>密码加密和验证逻辑在应用层处理，领域层只负责存储。</p>
     *
     * @param encodedPassword 加密后的密码
     */
    public void changePassword(String encodedPassword) {
        require(encodedPassword != null, AdminMessage.PASSWORD_WEAK);
        this.password = encodedPassword;
    }

    /**
     * 修改用户名。
     *
     * <p>需要验证格式，因此使用 update 方法而非简单的 Setter。</p>
     */
    public void updateUsername(String newUsername) {
        validateUsername(newUsername);
        this.username = newUsername;
    }

    /**
     * 修改昵称。
     *
     * <p>有非空校验逻辑，因此使用 update 方法而非简单的 Setter。</p>
     */
    public void updateNickname(String nickname) {
        if (nickname != null && !nickname.isBlank()) {
            this.nickname = nickname;
        }
    }

    /**
     * 启用管理员。
     */
    public void enable() {
        this.status = AdminUserStatus.ACTIVE;
    }

    /**
     * 禁用管理员。
     */
    public void disable() {
        this.status = AdminUserStatus.DISABLED;
    }

    /**
     * 添加角色关联。
     */
    public void addRole(Long roleId) {
        userRoles.add(new AdminUserRole(this.id, roleId));
    }

    /**
     * 清除所有角色关联。
     */
    public void clearRoles() {
        userRoles.clear();
    }

    /**
     * 获取角色 ID 列表。
     */
    public Set<Long> getRoleIds() {
        return userRoles.stream()
                .map(AdminUserRole::getRoleId)
                .collect(Collectors.toSet());
    }

    // ========== 私有方法 ==========

    private void validateUsername(String username) {
        Assertions.require(
            username != null && username.matches(USERNAME_PATTERN),
            AdminMessage.USERNAME_INVALID
        );
    }
}
```

**聚合根规范要点**：

1. 继承 `AuditableSoftDeletable`（**建议**：自动提供审计字段 + 软删除）
2. 实现 `AggregateRoot<T>` 接口
3. 使用 `@Aggregate` 注解标记
4. 简单字段使用 `@Getter` + `@Setter` 注解（字段级）
5. 有业务逻辑的方法手写（构造函数、业务方法）
6. 构造函数负责不变量校验（用户名格式）
7. `@PrePersist` 生成 TSID
8. **关联管理**：使用 `@OneToMany` + `orphanRemoval = true`，关联实体物理删除
9. **六边形架构**：
   - **领域层**：按职责定义接口（如 `domain/service/`），基础设施层提供适配器
   - **应用层**：接口和适配器都在基础设施层（分开文件）

**聚合根设计建议**：

| 设计决策 | 建议 | 原因 |
|---------|------|------|
| **继承基类** | 继承 `AuditableSoftDeletable` | 自动提供审计字段（createdAt/updatedAt）+ 软删除能力 |
| **软删除** | 推荐软删除 | 保留数据审计记录，支持数据恢复 |
| **ID 生成** | 使用 TSID | 分布式友好，时间排序 |
| **聚合大小** | 保持小聚合 | 减少锁竞争，提高并发性能 |

**什么时候不使用软删除？**
- 日志数据：量大且无需恢复
- 临时数据：会话信息、缓存数据
- 关联表实体：避免唯一索引冲突（见实体部分）

**六边形架构层次职责**：

| 功能 | 位置 | 原因 |
|------|------|------|
| **用户名格式校验** | 领域层 | 领域不变量（格式规则） |
| **密码强度规则** | 领域层 | 领域不变量（如"最少8位、含大小写字母"） |
| **密码加密器接口** | 领域层 | 南向端口接口（`PasswordEncoder`） |
| **密码加密实现** | 基础设施层 | BCrypt 适配器（`BCryptPasswordEncoderAdapter`） |
| **密码验证实现** | 基础设施层 | BCrypt 适配器 |
| **状态管理** | 领域层 | 领域核心逻辑 |
| **业务流程编排** | 应用层 | 北向接口适配层，组织领域服务完成业务场景 |

**架构说明**：
- **应用层**：北向接口（REST API、GraphQL、gRPC、MQ）的适配层，是限界上下文的出入口
- **领域层**：核心业务逻辑，定义南向端口接口
- **基础设施层**：南向接口的适配器实现（密码加密、持久化、缓存、外部服务等）
- **跨上下文调用**：其他上下文通过本上下文的应用层访问

### 2.2 实体（Entity）

**位置**：`domain/entity`

**命名规范**：`{Parent}{Entity}.java` 或 `{Entity}.java`

**核心原则**：关联表实体使用**单一代理主键**（符合 REL-001 规则），而非 JPA 复合主键。

**聚合根 vs 实体的继承原则**：

| 类型 | 继承基类 | 删除方式 | 原因 |
|------|---------|---------|------|
| **聚合根** | `AuditableSoftDeletable` | 软删除 | 独立生命周期，需保留审计记录 |
| **实体** | 无基类（仅实现接口） | 物理删除 | 依附聚合根，避免唯一索引冲突 |

**为什么实体不继承 AuditableSoftDeletable**？
1. **唯一索引冲突**：关联表有唯一约束（如 `admin_id + role_id`），软删除后重建关联会报错
2. **DDD 小聚合原则**：实体是聚合的一部分，生命周期由聚合根管理
3. **简化设计**：关联删除就是物理删除，无需保留审计记录

**错误示例**（软删除 + 唯一索引冲突）：
```
1. 删除 admin_id=1, role_id=2 → deleted=true
2. 再次添加 admin_id=1, role_id=2 → 数据库唯一索引报错！
```

**为什么使用代理主键**？
- ✅ 框架兼容性：`DomainEntity<T, ID>` 的 ID 参数为单一类型
- ✅ JPA 支持完整：与 `@GeneratedValue` 无缝集成
- ✅ 性能更优：单字段主键索引更高效
- ✅ 业务唯一性：通过数据库 `@UniqueConstraint` 保证

```java
@Entity
@Table(name = "sys_admin_user_roles", uniqueConstraints = {
    @UniqueConstraint(columnNames = {"admin_id", "role_id"})
})
@Getter
public class AdminUserRole implements DomainEntity<AdminUserRole, Long> {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id", nullable = false, updatable = false)
    private Long id;

    @Column(name = "admin_id", nullable = false)
    private Long adminId;

    @Column(name = "role_id", nullable = false)
    private Long roleId;

    /**
     * JPA 默认构造函数。
     */
    protected AdminUserRole() {
    }

    /**
     * 创建关联。
     */
    public AdminUserRole(Long adminId, Long roleId) {
        this.adminId = adminId;
        this.roleId = roleId;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        AdminUserRole that = (AdminUserRole) o;
        return Objects.equals(adminId, that.adminId) && Objects.equals(roleId, that.roleId);
    }

    @Override
    public int hashCode() {
        return Objects.hash(adminId, roleId);
    }
}
```

**实体规范要点**：

1. **不继承** `AuditableSoftDeletable`（**强烈建议**：避免唯一索引与软删除冲突）
2. 实现 `DomainEntity<T, ID>` 接口
3. 使用单一代理主键（`@GeneratedValue(strategy = GenerationType.IDENTITY)`）
4. 业务唯一性通过 `@UniqueConstraint` 保证
5. 重写 `equals()` 和 `hashCode()` 基于业务键（非主键）
6. 简单字段使用 `@Getter` 注解
7. **物理删除**：聚合根删除关联时直接调用 `repository.delete()`

**实体设计建议**：

| 设计决策 | 建议 | 原因 |
|---------|------|------|
| **继承基类** | **不继承** `AuditableSoftDeletable` | 避免唯一索引与软删除冲突 |
| **删除方式** | 物理删除 | 依附聚合根，无需独立审计记录 |
| **主键策略** | 单一代理主键 | 框架兼容性好，性能更优 |
| **业务唯一性** | `@UniqueConstraint` | 数据库保证，应用层校验 |

**为什么实体不继承 AuditableSoftDeletable（强烈建议）？**

1. **唯一索引冲突**：
   ```
   场景：管理员-角色关联表（admin_id, role_id）唯一约束

   1. 删除 admin_id=1, role_id=2 → deleted=true
   2. 再次添加 admin_id=1, role_id=2 → 数据库唯一索引报错！

   原因：数据库只看到 admin_id + role_id 已存在，不管 deleted 字段
   ```

2. **DDD 小聚合原则**：实体是聚合的一部分，生命周期由聚合根管理

3. **简化设计**：关联删除就是物理删除，无需保留审计记录

**什么时候实体可以继承 AuditableSoftDeletable？**
- 实体表**没有**唯一约束（不会冲突）
- 需要保留审计记录（如操作日志）
- 业务需要独立追溯实体历史

### 2.5 领域服务（DomainService）

**位置**：`domain/service`

**命名规范**：`{Scenario}Service.java` 或 `{DomainConcept}Service.java`

> **注意**：按场景命名，而非按模块。例如 `RolePermissionService`（角色权限相关）、`MenuTreeService`（菜单树构建）。

**何时使用**：
- 涉及多个聚合根的复杂领域逻辑
- 不属于任何单一聚合根的业务规则

**架构原则**：DomainService 不涉及 DTO

| 返回类型 | 说明 |
|---------|------|
| 领域模型（聚合根/实体） | ✅ 可以返回 |
| 基本类型（Long/void/boolean） | ✅ 可以返回 |
| DTO | ❌ 禁止涉及 |

```java
@DomainService
public class RolePermissionService {

    private final AdminRoleRepository roleRepository;
    private final PermissionScanner permissionScanner;

    public RolePermissionService(AdminRoleRepository roleRepository,
                                 PermissionScanner permissionScanner) {
        this.roleRepository = roleRepository;
        this.permissionScanner = permissionScanner;
    }

    /**
     * 验证权限码是否有效。
     *
     * @param permissionCodes 待验证的权限码
     * @return 无效的权限码列表
     */
    public List<String> validatePermissionCodes(Set<String> permissionCodes) {
        Set<String> validCodes = permissionScanner.scanByScope("admin").stream()
                .map(Permission::code)
                .collect(Collectors.toSet());

        return permissionCodes.stream()
                .filter(code -> !validCodes.contains(code))
                .toList();
    }

    /**
     * 检查角色是否拥有指定权限。
     */
    public boolean hasPermission(Long roleId, String permissionCode) {
        return roleRepository.findById(roleId)
                .map(role -> role.getPermissionCodes().contains(permissionCode))
                .orElse(false);
    }
}
```

**领域服务规范要点**：

1. 使用 `@DomainService` 注解
2. 构造函数注入
3. 不涉及 DTO 转换
4. 可以返回领域模型
5. 可以被 AppService 调用

### 2.6 枚举规范

**原则**：
- 枚举在领域层定义（`domain/enums/` 包）
- 前后端交互、后端与数据库交互统一以 **Integer code** 为准
- 推荐直接使用枚举类型参数，框架自动完成 Integer ↔ Enum 转换

#### 2.6.1 枚举定义

**枚举文件组织**：

- 枚举定义在独立的 `.java` 文件中（不嵌套在聚合根内）
- 位置：`domain/enums/` 包下
- 枚举类实现 `BaseEnum<T>` 接口

**示例**：`domain/enums/AdminUserStatus.java`
```java
package com.aieducenter.admin.domain.enums;

import com.cartisan.core.domain.BaseEnum;

/**
 * 管理员状态枚举。
 *
 * @since 0.1.0
 */
public enum AdminUserStatus implements BaseEnum<AdminUserStatus> {
    /**
     * 激活。
     */
    ACTIVE(1, "激活"),

    /**
     * 禁用。
     */
    DISABLED(0, "禁用");

    private final Integer code;
    private final String name;

    AdminUserStatus(Integer code, String name) {
        this.code = code;
        this.name = name;
    }

    @Override
    public Integer getCode() {
        return code;
    }

    @Override
    public String getName() {
        return name;
    }
}
```

**使用枚举**：
```java
import com.aieducenter.admin.domain.enums.AdminUserStatus;

@Entity
public class AdminUser extends AuditableSoftDeletable implements AggregateRoot<AdminUser> {

    @Getter
    @EnumConvert(AdminUserStatus.class)
    @Column(name = "status", nullable = false)
    private AdminUserStatus status;

    public boolean isActive() {
        return this.status == AdminUserStatus.ACTIVE;
    }

    public void enable() {
        this.status = AdminUserStatus.ACTIVE;
    }

    public void disable() {
        this.status = AdminUserStatus.DISABLED;
    }

```

**为什么枚举要独立文件？**
1. **复用性**：多个聚合根可以引用同一个枚举
2. **可读性**：文件职责单一，更易维护
3. **导入清晰**：`import com.aieducenter.admin.domain.enums.AdminUserStatus`

#### 2.6.2 架构边界规则

**推荐做法**：直接使用枚举类型参数，框架自动完成 Integer ↔ Enum 转换。

| 层级 | 处理方式 |
|------|---------|
| **Controller** | 直接使用枚举类型参数（@RequestParam、@RequestBody 字段、@PathVariable）|
| **AppService** | 直接使用枚举类型参数 |
| **Domain** | 定义枚举（独立文件） |
| **数据库** | 通过 @EnumConvert 自动转换为 Integer 存储 |

```java
// Controller - 直接使用枚举类型
import com.aieducenter.admin.domain.enums.AdminUserStatus;

@Operation(summary = "修改管理员状态")
public void updateStatus(
        @PathVariable Long id,
        @RequestParam AdminUserStatus status) {  // Spring MVC 自动转换 Integer → AdminUserStatus
    adminManagementAppService.updateStatus(id, status);
}

// AppService - 直接使用枚举类型
@Transactional
public void updateStatus(Long id, AdminUserStatus status) {
    AdminUser adminUser = requirePresent(
            adminUserRepository.findById(id),
            AdminMessage.ADMIN_NOT_FOUND
    );

    if (status == AdminUserStatus.ACTIVE) {
        adminUser.enable();
    } else {
        adminUser.disable();
    }

    adminUserRepository.save(adminUser);
}

// DTO 中直接使用枚举类型
public record AdminUserResponse(
    Long id,
    String username,
    AdminUserStatus status,      // Jackson 自动序列化为 Integer code
    String statusName        // MapStruct 自动调用 getName()
) {}

// 前端请求示例：
// PUT /api/v1/admin/users/1/status?status=0
// JSON 请求示例：
// { "status": 0 }  // 自动转换为 AdminUserStatus.DISABLED
```

**框架自动转换机制**（cartisan-boot 零配置支持）：

1. **@RequestParam / @PathVariable**：通过 `BaseEnumConverter` 自动转换 Integer → Enum
2. **@RequestBody**：通过 Jackson `BaseEnumDeserializer` 自动转换 Integer → Enum
3. **响应序列化**：通过 Jackson `BaseEnumSerializer` 自动转换 Enum → Integer
4. **数据库存储**：通过 JPA `@EnumConvert` + `UniversalEnumConverter` 自动转换 Enum ↔ Integer

> **零配置**：引入 `cartisan-web` 依赖即生效，通过 `CartisanWebAutoConfiguration` 自动注册 `BaseEnumConverter`。

**使用示例**：

```java
// Controller - 直接使用枚举类型
@Operation(summary = "修改管理员状态")
public void updateStatus(
        @PathVariable Long id,
        @RequestParam AdminUserStatus status) {  // ?status=1 自动转换为 AdminUserStatus.ACTIVE
    adminManagementAppService.updateStatus(id, status);
}

// AppService - 直接使用枚举类型
@Transactional
public void updateStatus(Long id, AdminUserStatus status) {

            adminUserRepository.findById(id),
            AdminMessage.ADMIN_NOT_FOUND
    );

    if (status == AdminUserStatus.ACTIVE) {
        adminUser.enable();
    } else {
        adminUser.disable();
    }

    adminUserRepository.save(adminUser);
}

// 前端请求示例：
// PUT /api/v1/admin/users/1/status?status=1  → 自动转换为 AdminUserStatus.ACTIVE
// PUT /api/v1/admin/users/1/status?status=0  → 自动转换为 AdminUserStatus.DISABLED
```

**BaseEnum 接口方法说明**：

- **`getCode()`**：返回 Integer 类型的编码（存储到数据库、序列化给前端）
- **`getName()`**：返回 String 类型的显示名称
- **`BaseEnum.requireByCode(Class, Integer)`**：通过 code 查找枚举（找不到抛异常）
- **`BaseEnum.parseByCode(Class, Integer)`**：通过 code 查找枚举（找不到返回 null）

**手动转换场景**（通常不需要，框架自动处理）：

```java
// 如果需要在代码中手动转换
import static com.cartisan.core.domain.BaseEnum.requireByCode;

AdminUserStatus status = requireByCode(AdminUserStatus.class, 1);
```

**禁止**：

1. **使用 String 传递枚举值**
```java
// ❌ 禁止：使用 String 参数
public void updateStatus(@PathVariable Long id, @RequestParam String status) {
    // ...
}

// ❌ 禁止：使用 valueOf() 方法
AdminUserStatus status = AdminUserStatus.valueOf(statusStr);
```

2. **前端使用枚举名称**
```javascript
// ❌ 禁止：前端使用枚举名称
{ "status": "ACTIVE" }

// ✅ 正确：前端使用 Integer code
{ "status": 1 }
```

### 2.7 常量规范

### 2.8 领域层解耦规范

**核心原则**：
> 领域层必须保持零外部依赖。所有外部框架、库、基础设施都通过端口接口解耦。

**禁止事项**：
```java
// ❌ 禁止：领域层直接依赖 Spring Framework
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
private static final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(10);

// ❌ 禁止：领域层直接依赖 Redis 客户端
import redis.clients.jedis.Jedis;
private Jedis jedis = new Jedis("localhost");

// ❌ 禁止：领域层直接依赖 HTTP 客户端
import org.springframework.web.client.RestTemplate;
private RestTemplate restTemplate = new RestTemplate();
```

**正确做法**：
```java
// ✅ 正确：通过端口接口解耦
@DomainService
public class PasswordEncoderService {
    private final PasswordEncoder encoder;
    // 领域服务封装南向端口
}

// ✅ 正确：端口接口定义在 domain/port
public interface PasswordEncoder {
    String encode(String rawPassword);
    boolean matches(String rawPassword, String encodedPassword);
}

// ✅ 正确：适配器实现在 infrastructure
@Adapter(PortType.CLIENT)
public class BCryptPasswordEncoderAdapter implements PasswordEncoder {
    // 基础设施层实现
}
```

**识别需要解耦的依赖检查清单**：
- [ ] Spring Security（密码编码、认证）
- [ ] Spring Data（数据库操作）
- [ ] Redis（缓存、消息队列）
- [ ] HTTP 客户端（外部服务调用）
- [ ] 消息队列（Kafka、RabbitMQ）
- [ ] 文件存储（OSS、S3）
- [ ] 邮件/短信发送
- [ ] 第三方支付

## 三、应用层规范

> **应用层定位**：北向接口的适配层，是限界上下文的出入口

### 3.1 应用服务（AppService）

**位置**：`application`

**命名规范**：`{Scenario}AppService.java`

**实际示例**（Admin 上下文）：
```
application/
├── AdminUserManagementAppService.java      # 管理员管理（CRUD）
├── AdminUserAuthAppService.java            # 管理员认证（登录、注销）
├── AdminUserPermissionAppService.java      # 管理员权限查询
├── MenuManagementAppService.java           # 菜单管理
├── RoleManagementAppService.java           # 角色管理
└── PermissionScanAppService.java           # 权限扫描
```

**命名原则**：
- 按业务职责命名
- 一个上下文可以有多个 AppService
- 体现具体业务场景（Management、Auth、Query 等）

**架构原则**：AppService 不应暴露领域模型给外部

| 返回类型 | 说明 |
|---------|------|
| DTO（Response） | 对外提供的数据 |
| 基本类型（Long/void/boolean） | 操作结果 |
| **领域模型** | ❌ 禁止对外暴露 |

```java
import static com.cartisan.core.util.Assertions.require;

@Service
public class AdminUserManagementAppService {

    private final AdminUserRepository adminUserRepository;
    private final AdminUserMapper adminUserMapper;

    public AdminUserManagementAppService(
            AdminUserRepository adminUserRepository,
            AdminUserMapper adminUserMapper) {
        this.adminUserRepository = adminUserRepository;
        this.adminUserMapper = adminUserMapper;
    }

    /**
     * 查询管理员列表（分页）。
     */
    @Transactional(readOnly = true)
    public PageResponse<AdminUserResponse> findAll(AdminUserQuery query, Pageable pageable) {
        Specification<AdminUser> spec = ConditionSpecifications.fromAnnotation(query);
        Page<AdminUser> page = adminUserRepository.findAll(spec, pageable);

        return new PageResponse<>(
                adminUserMapper.convertList(page.getContent()),
                page.getTotalElements(),
                pageable.getPageNumber() + 1,
                pageable.getPageSize()
        );
    }

    /**
     * 查询管理员详情。
     */
    @Transactional(readOnly = true)
    public AdminUserResponse findById(Long id) {
        AdminUser adminUser = adminUserRepository.findById(id)
                .orElseThrow(() -> new ApplicationException(AdminMessage.ADMIN_NOT_FOUND));

        return adminUserMapper.convert(adminUser);
    }

    /**
     * 创建管理员。
     */
    @Transactional
    public Long create(CreateAdminUserCommand command) {
        require(
                !adminUserRepository.existsByUsername(command.username()),
                AdminMessage.USERNAME_ALREADY_EXISTS
        );

        AdminUser adminUser = new AdminUser(command.username(), command.password(), command.nickname());
        AdminUser saved = adminUserRepository.save(adminUser);
        return saved.getId();
    }

    /**
     * 更新管理员。
     */
    @Transactional
    public void update(Long id, UpdateAdminUserCommand command) {
        AdminUser adminUser = adminUserRepository.findById(id)
                .orElseThrow(() -> new ApplicationException(AdminMessage.ADMIN_NOT_FOUND));

        // 业务逻辑...
        adminUserRepository.save(adminUser);
    }

    /**
     * 删除管理员。
     */
    @Transactional
    public void delete(Long id) {
        AdminUser adminUser = adminUserRepository.findById(id)
                .orElseThrow(() -> new ApplicationException(AdminMessage.ADMIN_NOT_FOUND));

        adminUserRepository.delete(adminUser);
    }
}
```

**应用服务规范要点**：

1. 使用 `@Service` 注解
2. 构造函数注入（禁止 `@Autowired` 字段注入）
3. 读操作用 `@Transactional(readOnly = true)`
4. 写操作用 `@Transactional`
5. **禁止暴露领域模型**：返回类型只能是 DTO、基本类型（Long/void/boolean）
6. 复杂领域逻辑考虑创建 DomainService（按需，非必须）

## 四、北向接口适配器层规范

> **endpoints 层定位**：北向接口适配器，是外部系统驱动本上下文的入口
> - 包括 REST API、外部 API、MQ Listener、定时任务等
> - 所有 endpoints 都通过应用层访问领域逻辑
> - 不包含业务逻辑，只负责协议转换和调用应用服务

### 4.1 前端 REST API Controller（内部调用）

**位置**：`endpoints/controller`

**命名规范**：`{Resource}Controller.java`

**用途**：供内部前端（Next.js、Vue 等）调用

**URL 规范**：`/api/v1/{context}/{resources}`

```java
@RestController
@RequestMapping("/api/v1/admin/admin-users")
@Validated
@Tag(name = "Admin Users", description = "管理员管理")
public class AdminUserController {

    private final AdminUserManagementAppService adminManagementAppService;

    public AdminUserController(AdminUserManagementAppService adminManagementAppService) {
        this.adminManagementAppService = adminManagementAppService;
    }

    @GetMapping
    @RequireAuth
    @RequirePermission(
        value = "admin:user:read",
        name = "平台管理 / 用户管理 / 查看",
        scope = "admin"
    )
    @Operation(summary = "查询管理员列表（分页）")
    public PageResponse<AdminUserResponse> findAll(
            AdminUserQuery query,
            @PageableDefault(size = 20) Pageable pageable) {
        return adminManagementAppService.findAll(query, pageable);
    }

    @PostMapping
    @RequireAuth
    @RequirePermission(
        value = "admin:user:write",
        name = "平台管理 / 用户管理 / 编辑",
        scope = "admin"
    )
    @Operation(summary = "创建管理员")
    public Long create(@Valid @RequestBody CreateAdminUserCommand command) {
        return adminManagementAppService.createAndReturnId(command);
    }
}
```

**控制器规范要点**：

1. 构造函数注入
2. 类级别加 `@Validated`
3. 权限注解：
   - `@RequireAuth`：需要登录
   - `@RequirePermission`：需要指定权限（`{context}:{module}:{action}` 格式）
4. 参数校验使用 `@Valid`
5. Swagger 注解：`@Tag`（类级别）、`@Operation`（方法级别）
6. 返回类型：`PageResponse<T>` 或具体 DTO/Long/void
7. URL 规范：`/api/v1/{context}/{resources}`

### 4.2 外部 API Controller（第三方调用）

**位置**：`endpoints/api/v1`

**命名规范**：`{Resource}ApiV1Controller.java`

> **重要**：类名必须包含版本号（如 `V1`），避免多版本共存时 Spring Bean 名称冲突。

**用途**：供第三方系统、移动端、开放平台调用

**URL 规范**：`/api/v1/external/{context}/{resources}`

**与前端 Controller 的差异**：

| 维度 | 前端 Controller | 外部 API Controller |
|------|-----------------|---------------------|
| **位置** | `endpoints/controller` | `endpoints/api/v1` |
| **命名** | `{Resource}Controller` | `{Resource}ApiV1Controller` |
| **URL 路径** | `/api/v1/{context}/{resources}` | `/api/v1/external/{context}/{resources}` |
| **认证方式** | Session/JWT | API Key/OAuth2.0 |
| **权限控制** | `@RequirePermission` | API Key 权限 |
| **限流策略** | 用户级 | API Key 级 |
| **版本控制** | 相对宽松 | 严格版本管理（v1/v2） |
| **错误响应** | 可返回详细错误 | 标准化错误码 |
| **文档要求** | 内部文档 | 公开 API 文档 |

**示例**：
```java
@RestController
@RequestMapping("/api/v1/external/admin/admin-users")
@Validated
@Tag(name = "External Admin Users API v1", description = "外部管理员管理 API v1")
public class AdminUserApiV1Controller {

    private final ApiKeyAuthenticator apiKeyAuthenticator;
    private final AdminUserManagementAppService adminManagementAppService;

    public AdminUserApiV1Controller(
            ApiKeyAuthenticator apiKeyAuthenticator,
            AdminUserManagementAppService adminManagementAppService) {
        this.apiKeyAuthenticator = apiKeyAuthenticator;
        this.adminManagementAppService = adminManagementAppService;
    }

    @GetMapping("/{id}")
    @ApiKeyAuth  // API Key 认证
    @RateLimit(rate = 100, interval = 60)  // 限制：每分钟 100 次
    @Operation(summary = "查询管理员详情（外部 API v1）")
    public ApiResponse<AdminUserResponse> getById(@PathVariable Long id) {
        AdminUserResponse response = adminManagementAppService.findById(id);
        return ApiResponse.success(response);
    }
}
```

**多版本共存示例**：
```java
// v1 API - 保持向后兼容
@RestController
@RequestMapping("/api/v1/external/admin/admin-users")
public class AdminUserApiV1Controller {
    // v1 版本实现
}

// v2 API - 新增功能
@RestController
@RequestMapping("/api/v2/external/admin/admin-users")
public class AdminUserApiV2Controller {
    // v2 版本实现（可能包含破坏性变更）
}
```

**外部 API Controller 规范要点**：

1. **类名包含版本号**：`{Resource}ApiV1Controller`，避免 Bean 名称冲突
2. 使用 API Key 认证（或 OAuth2.0）
3. 添加严格的限流注解（按 API Key）
4. 返回统一的响应格式（`ApiResponse<T>`）
5. 错误码标准化，不暴露内部实现细节
6. URL 中包含 `external` 前缀，标识为外部 API
7. 严格的版本控制（v1、v2 共存）
8. 完善的 API 文档（Swagger/OpenAPI）

### 4.3 消息队列监听器（MQ Listener）

**位置**：`endpoints/listener`

**命名规范**：`{Event}Listener.java` 或 `{Event}MessageListener.java`

**用途**：监听消息队列消息，接收后调用应用服务处理

**与 Controller 的关系**：

| 维度 | REST Controller | MQ Listener |
|------|-----------------|-------------|
| **触发方式** | HTTP 请求 | 消息队列消息 |
| **同步/异步** | 同步（阻塞） | 异步（非阻塞） |
| **返回值** | 立即返回响应 | 确认消息接收 |
| **错误处理** | 返回错误响应 | 死信队列或重试 |
| **典型场景** | 前端交互、外部 API | 异步任务、事件通知 |

**示例**：
```java
@Component
@RequiredArgsConstructor
public class UserCreatedListener {

    private final AdminUserManagementAppService adminUserManagementAppService;

    /**
     * 监听用户创建事件，自动创建管理员账号。
     */
    @RabbitListener(queues = "user.created")
    public void handleUserCreated(UserCreatedEvent event) {
        try {
            // 调用应用服务处理
            adminUserManagementAppService.createAdminForUser(event.getUserId(), event.getUsername());
        } catch (Exception e) {
            // 异常处理：记录日志，消息会进入重试队列或死信队列
            log.error("Failed to handle user created event: {}", event, e);
            throw e;  // 抛出异常让 MQ 框架处理重试
        }
    }

    /**
     * 监听用户删除事件，级联删除管理员账号。
     */
    @RabbitListener(queues = "user.deleted")
    public void handleUserDeleted(UserDeletedEvent event) {
        try {
            adminUserManagementAppService.deleteByUserId(event.getUserId());
        } catch (Exception e) {
            log.error("Failed to handle user deleted event: {}", event, e);
            throw e;
        }
    }
}
```

**MQ Listener 规范要点**：

1. **包位置**：`endpoints/listener`
2. **命名规范**：`{Event}Listener.java` 或 `{Event}MessageListener.java`
3. **注解**：使用 `@Component` 或 `@RabbitListener`（根据 MQ 框架）
4. **构造函数注入**：注入需要的 AppService
5. **异常处理**：
   - 记录详细日志
   - 抛出异常让 MQ 框架处理重试
   - 避免吞掉异常导致消息丢失
6. **幂等性**：确保消息重复处理时不会产生副作用（如使用 `saveOrUpdate` 而非 `save`）
7. **事务管理**：
   - Listener 方法通常不加 `@Transactional`
   - AppService 方法内部加 `@Transactional`
   - 避免事务跨越消息接收边界

**包结构示例**：
```
endpoints/
├── controller/              # REST API
│   └── AdminUserController.java
├── api/                     # 外部 API
│   └── v1/
│       └── AdminUserApiV1Controller.java
├── listener/                # 消息队列监听器
│   ├── UserCreatedListener.java
│   └── UserDeletedListener.java
└── scheduler/               # 定时任务（按需）
    └── DataSyncScheduler.java
```

### 5.2 迁移脚本规范

**位置**：`src/main/resources/db/migration`

**命名规范**：`V{version}__{description}.sql`

```sql
-- ========================================================================
-- {Context Name} Context: {Description}
-- ========================================================================

-- 主表
CREATE TABLE {prefix}_{table_name} (
    id              BIGINT PRIMARY KEY,
    name            VARCHAR(50) NOT NULL,
    -- 其他字段...
    created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by      BIGINT,
    updated_by      BIGINT,
    deleted         BOOLEAN NOT NULL DEFAULT FALSE
);

-- 关联表
CREATE TABLE {prefix}_{relation_table} (
    parent_id       BIGINT NOT NULL,
    child_id        BIGINT NOT NULL,
    PRIMARY KEY (parent_id, child_id)
);

-- 索引（软删除过滤）
CREATE INDEX idx_{prefix}_{table}_{column} ON {prefix}_{table_name}({column}) WHERE deleted = FALSE;

-- 外键
ALTER TABLE {prefix}_{relation_table} ADD CONSTRAINT fk_{prefix}_{relation}_{parent}
    FOREIGN KEY (parent_id) REFERENCES {prefix}_{parent_table}(id);
```

**标准字段**：
- `id`：BIGINT 主键（TSID）
- `created_at`、`updated_at`：审计时间
- `created_by`、`updated_by`：审计人（BIGINT）
- `deleted`：软删除标记（BOOLEAN，默认 FALSE）

## 七、工具库使用规范（hutool）

### 7.1 集合初始化

**使用 hutool 替代 Java 标准库**：

| Java 标准库 | hutool 替代 |
|------------|-------------|
| `new HashSet<>()` | `CollUtil.newHashSet()` |
| `new ArrayList<>()` | `CollUtil.newArrayList()` |
| `new HashMap<>()` | `MapUtil.newHashMap()` |

```java
import cn.hutool.core.collection.CollUtil;
import cn.hutool.core.map.MapUtil;

// 推荐
Set<Long> roleIds = CollUtil.newHashSet();
List<AdminMenu> roots = CollUtil.newArrayList();
Map<Long, AdminMenu> menuMap = MapUtil.newHashMap();

// 不推荐
Set<Long> roleIds = new HashSet<>();
List<AdminMenu> roots = new ArrayList<>();
Map<Long, AdminMenu> menuMap = new HashMap<>();
```

### 7.2 Stream 收集操作

**Stream 操作仍使用 Java 标准库 Collectors**（hutool 不支持 Stream）：

```java
import java.util.stream.Collectors;

// Stream to List
List<String> names = users.stream()
    .map(User::getName)
    .collect(Collectors.toList());

// Stream to Set
Set<Long> ids = roles.stream()
    .map(AdminRole::getId)
    .collect(Collectors.toSet());
```

### 7.3 Java 语言特性保持不变

以下情况继续使用 Java 标准库：

| 场景 | 用法 | 说明 |
|------|------|------|
| 空不可变集合 | `List.of()` | Java 9+，性能最优 |
| Stream 终止操作 | `.toList()` | Java 16+，比 `Collectors.toList()` 更高效 |
| Optional | `Optional.ofNullable()` | Java 标准库 |
| Objects 工具 | `Objects.equals()` | Java 标准库 |

```java
// 推荐（Java 语言特性）
return List.of();  // 空不可变列表
return stream.toList();  // Java 16+ Stream 收集
return Optional.ofNullable(value);  // Optional 包装
if (Objects.equals(a, b)) { }  // null 安全比较
```

## 十一、检查清单

新建上下文时，确保：

**基础结构**
- [ ] `package-info.java` 说明文件
- [ ] 聚合根**建议**继承 `AuditableSoftDeletable`（使用 `@Getter`/`@Setter` 注解）

- [ ] AppService 不暴露领域模型，只返回 DTO/基本类型

- [ ] Controller 使用 `@RequirePermission` 注解
- [ ] DTO 使用 Record + 校验注解
- [ ] Mapper 继承 `DomainMapper`

**代码风格**
